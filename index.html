What it is, in plain words

Lots of decisions are supposed to need more than one person to agree: releasing to production, granting admin access, approving a payment, merging a sensitive change, a board vote. The rule is usually written as "needs N of M" — two of three leads, a majority of the board, any threshold you like.

The weak point is never the rule. It's the counting. In practice the tally lives in a chat thread or an inbox, and it quietly breaks: the same person approves twice from two accounts, an approval from someone with no authority gets counted, a heavier vote is treated the same as a light one, or nobody actually checks that the threshold was met before the action went ahead.

QuorumGate is the referee for that count. You hand it the approvals and the threshold; it collapses duplicate voters to a single vote, drops malformed entries, tallies the real weight behind each choice, and returns one honest verdict: met or not met, with the winning choice and the full breakdown. It is a tiny pure function — the same code that is proven by a mutation gate is the code that runs on this page.

Start here — how to use it

On this page (no install)

  1. Scroll to Try it.
  2. Add each approver: a name, their weight (use 1 for one-person-one-vote), and what they approved (the choice, e.g. release).
  3. Set the threshold — the total distinct-voter weight that must be cast for the count to clear (met compares the threshold to the total participating weight, not the winning choice alone).
  4. Read the verdict. Try a preset to see a double-vote attack get caught.

In your own system (3 lines)

import { tallyQuorum } from './kernel.mjs';

const r = tallyQuorum(
  [ {voter:'ada', weight:1, choice:'release'},
    {voter:'ada', weight:1, choice:'release'} ], // ada again — not two people
  2);
// r.met === false  (ada collapses to one vote → total 1, below the threshold of 2)

One file, zero dependencies. Copy kernel.mjs into any JS/TS runtime, a CI step, a serverless function, or an agent tool.

How it works — traced from a real run

Take the double-vote attack preset: three approvals, but two of them are ada voting twice. The rule needs 3 distinct approvers. A naive count of the three rows reads 3 and would wave it through. Here is what the kernel does instead, step by step — the numbers below are the actual run.

Every edge of the threshold is what the mutation gate attacks: it rewrites >= to >, flips the dedupe, lets a negative weight through — and each of the 19 rewrites is caught by a test. That is what "19/19 killed" means: no mutant among the 19 the tool tried survives the tests — a hard bar on the tests, not a proof the logic is complete.

For buyers — what QuorumGate does for your business

A quorum rule you cannot prove was met is a control that exists only on paper. QuorumGate turns "two people approved this" from a claim in a chat log into a verifiable tally with a re-runnable proof. Here is what that means for each role.

For the CISO / Head of Risk

Separation-of-duties and four-eyes controls become evidence, not trust. Every gated action carries a tally showing the distinct voters and the weight behind each choice — the artefact an auditor asks for. (It does not itself check a voter is authorised; pair it with your roster/signer for that, as the white paper states.) The logic is a 40-line pure function you can read in a sitting, not a black box.

For the CTO / Eng lead

Drop it into CI, a merge check, a deploy step, or an agent's tool-belt. Zero dependencies, no network, no secrets to manage. It never throws on bad input, so it can't take your pipeline down — malformed data returns a clean {ok:false}.

For the COO / Ops

The approvals that gate releases, access and payments stop living in someone's inbox. The count is automatic, the double-vote and the junk entry are rejected by construction, and the verdict is the same every time anyone re-runs it.

For the Board / CFO

Weighted votes are first-class: a director with a larger stake carries more weight, and the tally reflects it. Governance decisions get a reproducible record. Nothing is sent to a vendor cloud, so there is no new data-processing agreement to sign.

White paper — the short version

The problem. N-of-M approval is the most common integrity control in an organisation, and the most quietly broken. The rule is sound; the counting is done by hand, in channels that don't enforce distinctness, weight, or the threshold. An attacker — or an honest mistake — pads the count, and the action proceeds as if the quorum were real.

The claim. The count should be a pure, deterministic function with no I/O, so it can be run anywhere, re-run identically by anyone, and proven. QuorumGate collapses duplicate voters to a single vote, discards malformed weights without throwing, tallies weight per choice, and compares the total participating weight to the threshold (met = total >= threshold; the winner is reported separately as the plurality choice). The result is total, honest, and reproducible.

Why a mutation gate, not just tests. Passing tests prove the code works on the cases you thought of. A mutation gate proves the tests work: it rewrites the kernel 19 ways — >=→>, dedupe removed, negative weights admitted — and demands the tests catch every one. 19/19 killed means the suite catches those 19 rewrites — a hard bar on the tests, not a proof the logic is complete. This is the estate's one defensible idea: trust comes from a gate that survives attack, not from a green checkmark.

What it is not. QuorumGate judges the tally. met measures distinct participating weight against the threshold; the winner is the plurality choice, ties broken by the order votes arrive — it does not compute a majority. In the common sign-off case you feed it only the approvals of one action, so participation is the approval weight and met means "N distinct approvers cleared the bar". It does not verify that a voter is who they claim (a signer's job) or that they are on the authorised roster (policy). It is designed to compose with those — the referee for the count, not the whole stadium.

Risks, answered

"A bad actor forges an approval."Out of scope by design — pair with a signer.
"Someone sets the threshold too low."Policy, and visible — the threshold is in the record.
"Weights could be gamed."Weights are your input; gate who can set them upstream.
"The code could change silently."CI re-runs the gate; a drifting kernel fails 19/19.
